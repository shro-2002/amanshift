## 1. Data quality and provenance (T-DQ)

- T-DQ-01 Each fetch stores URL, retrieval time, SHA-256, row count in `eval/out/manifest.json`.
- T-DQ-02 METAR: keep on-the-hour reports (`HH:00`, deduplicated); reject T outside [0, 55] °C, RH outside [1, 100] %, wind > 40 m/s; report % removed per year.
- T-DQ-03 Forecast: no nulls in required variables; report missing-hour count.
- T-DQ-04 Join forecast and METAR in UTC on exact hour; report paired-hour counts per year (feasibility check on 2025-06-01..09-30 gave 2,927 paired hours; to be regenerated by script).
- Acceptance: ≥ 90 % of season hours paired per year, else that year is excluded and reported.

## 3. Historical day-ahead forecast evaluation

**Question:** if a supervisor had used AmanShift's day-ahead screening, how well would the warnings have anticipated conditions derived from what was later observed at Abu Dhabi airport?

- Location: OMAA (24.433 N, 54.651 E). Season: 1 Jun – 30 Sep, daylight work hours 07:00–18:00 GST.
- Forecast-based estimate: thermofeel Liljegren with `*_previous_day1` T, RH, surface pressure, 10 m wind, instantaneous shortwave and direct radiation.
- **Observation-based reference** (two variants, both reported):
  - **REF-SHADE (primary, more independent):** observed T, RH, wind with radiation set to diffuse only (fdir = 0, ssrd = forecast diffuse). Shares only the diffuse radiation term with the forecast.
  - **REF-SUN (secondary, partly circular):** observed T, RH, wind with forecast shortwave/direct radiation (METAR has no radiation). Explicitly flagged as partly dependent on the forecast.
- Primary profile uses REF-SHADE (shaded outdoor exposure); direct-sun profiles use REF-SUN and are labelled partly circular. P1: replace forecast radiation in the references with ERA5 radiation from the Open-Meteo historical archive to reduce circularity.
- Event: hour where the reference-based level ≥ k (k = 3 "work/rest required" primary; k = 4 secondary) for a profile; primary profile = moderate work (348.9 W), work clothes, acclimatized, shaded outdoor, covered by shade. Secondary profiles: light/acclimatized, heavy/acclimatized, moderate/unacclimatized.
- Level-wise evaluation uses the same level function on both sides.

### Metrics (hour level, per profile)

POD = TP/(TP+FN); FAR = FP/(TP+FP); CSI = TP/(TP+FP+FN); bias ratio = (TP+FP)/(TP+FN); exact level agreement and **under-warning rate** = share of hours where forecast level < reference level (safety-critical); MAE and bias of WBGT estimate. Event level: for each day with ≥ 1 reference exceedance, **lead time** is fixed by design (day-ahead warning available by 18:00 GST on D-1, i.e., ≥ 13 h before the first work hour) and is reported as such, not as a skill metric; skill is captured by missed days = days with exceedance but no forecast exceedance.

P1: bootstrap 95 % CIs by resampling days (1,000 resamples, seed 20261119). P0: point estimates with event and day counts.

### Chronological holdout and leakage prevention
- Train/tune: summers 2022, 2023, 2024. Holdout: 2026 = clean holdout (never inspected); 2025 = holdout exposed to the untuned planning smoke test (reported separately, labelled).
- Only one tuned parameter: forecast margin δ ∈ {0, 0.5, 1.0, 1.5, 2.0} °C, chosen on train as the smallest δ with under-warning rate ≤ 5 % for the primary profile. Frozen in `policy` before holdout is run; the script refuses to read holdout files until `delta_frozen.json` exists (T-EVAL-LEAK-01).
- The 2025 feasibility smoke test (run during planning, no thresholds tuned) is excluded from all tuning; δ is selected on 2022–2024 only.
- No observation from day D enters a forecast for day D (previous_day1 only).

### Baselines (same metrics)
B1 clock rule: STOP 12:30–15:00 from 15 Jun–15 Sep, else level 1. B2 air-temperature rule: level from forecast T thresholds tuned on train to match train event rate. B3 persistence: yesterday's observation-based level at the same hour. B4 raw forecast (δ = 0). AmanShift = forecast + δ.

Acceptance: report everything, including where AmanShift is worse. Failure condition: under-warning rate on holdout > 10 % for primary profile → state prominently and raise δ only in a clearly labelled post-hoc sensitivity table.

Limitations to print with results: airport ≠ construction site; METAR lacks radiation and globe temperature; Liljegren is a model of WBGT, not a measurement; one grid point; no surface heat (asphalt, steel).

## 4. Fail-safe property tests (T-KER, hypothesis)

Generators: random snapshots (1–12 crews, 1–10 resources, random classes, WBGT 20–40 °C, random provenance and ages, random time incl. midday window). Degradation operators: forecast fresh→stale→lost (cached value retained); resource up→unconfirmed→unknown→down; back-date `retrieved_at` or `last_confirmed_at` by Δ; connectivity online→offline. `eval_time`, crews, policy and meter/TWL readings are never changed or removed (fixed κ, append-only).

| Test | Property |
|---|---|
| T-KER-01 | For every s and degradation d: `permitted(d(s)) ⊆ permitted(s)` |
| T-KER-02 | `level(d(s)) ≥ level(s)` for every crew |
| T-KER-03 | Composition: random sequences of 1–6 degradations preserve 01–02 |
| T-KER-04 | Planner output on d(s) is approved by checker |
| T-KER-05 | Adding a lower meter reading never lowers level; higher may raise |
| T-KER-06 | Recovery: no level decrease before dwell and confirmation |
| T-KER-07 | Determinism: same snapshot → identical plan hash |

Sample size: 10,000 examples for T-KER-01/02 (`max_examples=10000`, derandomized seed), 2,000 for T-KER-03/04. Rationale: runs in < 3 min on M4; enough to cover all 4×4×4×4 class combinations many times. Artifact: `eval/out/property_tests.json` with counts and 0 failures required.

## 5. Checker mutation testing (T-CHK)

- **Plan mutants (P0):** from each approved plan on 500 generated snapshots, apply mutation operators: raise work fraction one step; assign a down/unknown resource; exceed capacity; exceed walk limit; remove a crew; duplicate a crew; drop RED to work; ignore midday window; ignore escalation; mismatch snapshot id; assign unacclimatized crew REL instead of RAL. A mutant that violates a rule must be rejected. Equivalent mutants (that remain valid, e.g., lowering work fraction) are classified automatically by an oracle that recomputes from the policy table and excluded. Metric: kill rate = rejected / non-equivalent. Acceptance ≥ 95 %; list survivors. Because mutants and oracle derive from the same rule list, this measures rule coverage, not independence; independence evidence is T-CHK-DIFF (10,000 random plans: checker verdict = membership of plan in kernel A_c; disagreements reported and investigated) plus 10 hand-computed adversarial cases in `tests/golden/checker_cases.json`.
- **Code mutants (P1):** `mutmut` on `amanshift_checker` with the checker test suite; report mutation score.
- Artifact: `eval/out/checker_mutation.json`.

## 6. Planner benchmarks (SYNTH-TEST)

200 synthetic sites per size tier (4, 8, 12 crews; 3, 6, 10 resources), 1–2 random resource failures each. Compare: AmanShift planner vs greedy (nearest available resource in crew order) vs no-replan (keep previous assignment). Metrics: priority-weighted unprotected persons (stage-1 value), crews stopped, checker violations, runtime p50/p95. Acceptance: 0 checker violations for every planner; MILP (if built) stage-1 value ≤ greedy on every instance; runtime p95 ≤ 1 s. Artifact: `eval/out/planner_bench.json`.

## 7. Cost of safety
On holdout days with the SIM-SITE, compute permitted work-hours under full information vs (a) stale forecast, (b) forecast missing (climatology bound), (c) offline > 1 h, (d) offline > 3 h. Report the % reduction. Labelled SIM-SITE + HIST-FCST.

## 8. Network disconnection and offline expiry (T-OFF)

- T-OFF-01 (fast-check, 5,000 cases): for any pack and elapsed time, displayed level ≥ cached level.
- T-OFF-02 elapsed ≥ stale_after ⇒ displayed = max(planned, worst_case); elapsed ≥ expires_at ⇒ 4. Local confirmations never change the displayed level.
- T-OFF-03 elapsed = max(now_wall − pack_issued_at, persisted_max_elapsed), persisted in IndexedDB on every tick; a wall clock earlier than the last seen value ⇒ treat as expired (level 4). Reloading offline cannot reset elapsed time.
- T-OFF-04 Playwright: load S2, set context offline, assert banner within 5 s, reload page offline, app shell loads from service worker.

## 14. Future field-pilot protocol (NOT-VALIDATED today)

- Design: stepped-wedge across 3 sites × 1 hot season (sites start AmanShift at staggered 3-week intervals); control period = usual practice.
- Measures: onsite WBGT per zone every 30 min (calibrated meter); **adherence** = % of prescribed rest periods taken (supervisor log + spot audits); **symptoms** = anonymous crew-level self-reports per 1,000 worker-hours; **emergency escalations** and heat-illness incidents from site medical logs; **compliance** with ADPHC requirements (audit checklist); **lost work time** = stopped hours vs scheduled; **alert lead time** and **false alarms** against onsite measurements; **translation quality** = comprehension test with 20 workers per language (target ≥ 90 % correct action identification) before deployment.
- Ethics: independent ethics review; no individual data; workers can decline any participation without consequence; data-sharing agreement banning employment use.
- Primary outcome for a later effectiveness study: heat-related illness incidence per 100,000 worker-hours (needs larger multi-season sample; power calculation deferred to pilot data).
